# Six-Month Roadmap — Planning Baseline

Timing is a working hypothesis, not a delivery commitment. Sequence work by evidence gates and contributor/reviewer availability.

## Current baseline

**Verified repository fact:** main `0c62587` includes a fixture-backed React interface and a separate pure-Python diagnostic prototype with unit tests. These are partial foundations, not a connected learning product. API, database, authentication, real sessions, evaluated diagnosis and mastery remain planned. See [handoff](../HANDOFF.md).

1. **Month 1 / Phase 0 — Desk research and feasibility:** authoritative syllabus verification; competitor/substitute matrix; public problem evidence; provisional Mechanics concept map/taxonomy; diagnostic evaluation design; pilot access/consent and baseline metrics. Interviews are optional follow-up. Gate: the [Phase 0 exit criteria](PHASE_0_EXECUTION_PLAN.md) are reviewed, uncertainties recorded and a bounded next step approved. Do not begin broad backend implementation while scope and feasibility remain unreviewed.
2. **Month 2 — Content and diagnosis validation:** qualified teacher review of objectives, prerequisite edges, items/keys/distractors, diagnostic evidence and abstention semantics; independent annotations and bounded prototype evaluation. Gate: reviewed content and agreed validity/false-positive criteria; public research is not teacher approval or direct student validation.
3. **Month 3 — Foundations and student slice:** after discovery/content gates, approve one narrow identity/consent, assessment/evidence/report slice with persistence and server-side authorization. Reuse the existing interface and domain code only where validated. Gate: a real integrated student workflow with appropriate tests and auditability.
4. **Month 4 — Repair and tutor slice:** reviewed intervention, independent transfer tasks, delayed reassessment and authorized tutor aggregation/assignment. Gate: functioning student/tutor loop, privacy and accessibility checks; fixture screens alone do not satisfy it.
5. **Month 5 — Pilot:** only after access, consent, safeguarding, security and content readiness review; collect defined baseline, completion, teacher-adjudicated diagnostic quality, transfer and delayed outcomes. Gate: interpretable results with sample coverage and limitations.
6. **Month 6 — Decision:** review quality, false positives, outcomes, usability, operating feasibility and any approved value research. Decide expand, narrow, pause or stop. No expansion based solely on passing unit tests or synthetic examples.

Two contributors are confirmed; ownership, capacity, reviewer availability and pilot access remain open questions. Assign owners and dates at Phase 0 kickoff; do not infer a founder role split.
